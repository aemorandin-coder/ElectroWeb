# C-02 — DTO público de producto
Estado: HECHO
Rama: claude/C-02 (desde `main`; no depende de C-01/C-05/C-10/C-11)

## Qué cambió
- **`lib/dto/product.ts` (nuevo)**
  - `toPublicProduct()` con lista blanca de campos: id, name, slug, shortCode, description, priceUSD, compareAtPriceUSD, stock, images (array), mainImage, productType, digitalPlatform, digitalRegion, category {id, name, slug}, brand {name, slug}, isFeatured, createdAt (ISO), specs, features (array) y SEO. Todos los Decimal salen como `number`.
  - Además de la lista del plan incluye **deliveryMethod, weightKg, dimensions, isConsolidable y shippingCost**: el detalle los necesita para exigir el usuario en recargas manuales y para calcular el envío en el checkout. No son datos sensibles.
  - **Nunca salen:** costPerItem, barcode, minStock, sku, priceVES, tags, status, categoryId/brandId ni updatedAt.
  - **Hallazgo nuevo:** `specs.digitalPricing` guardaba el **costo** de cada denominación digital y salía completo en la API y en el HTML. El DTO deja solo `{ amount, salePrice }` de las denominaciones habilitadas.
  - `publicProductInclude` trae solo id/name/slug de la categoría y name/slug de la marca.
- **`/api/products/public`** y **`/api/products/slug/[slug]`** responden con el DTO. `limit` queda acotado a 1–100: antes `?limit=abc` mandaba `NaN` a Prisma.
- **`GET /api/products`** exige `MANAGE_PRODUCTS` o `MANAGE_CONTENT` (403 si no). Lo usan el admin de productos y `SocialMediaGenerator` en Marketing. Con solo `MANAGE_CONTENT`, `costPerItem` sale `null`. Ninguna pantalla pública lo consumía (verificado con grep).
- **`GET /api/products/[id]`** (fuera de la lista del plan, mismo problema): antes bastaba **cualquier sesión, incluido un cliente**, para leer borradores y `costPerItem`. Ahora exige `MANAGE_PRODUCTS`. Lo usan los formularios de admin; `/comparar` también, pero ya estaba rota y C-06 la elimina (D1).
- **Home, `/productos` y `/categorias/[category]`:** consultan con `publicProductInclude` y pasan `products.map(toPublicProduct)` a los componentes cliente. Se acabó el `JSON.parse(JSON.stringify(producto))` que metía el costo en el HTML.
- **`/categorias`:** el contador de productos cuenta solo los publicados (antes sumaba borradores).
- **Tipos cliente** (`ProductCarousel`, `CategoryClient`, `ProductosClient`, `ProductClient`): se quita `status` y `brand` pasa a `{ name, slug }`. `ProductClient` muestra `product.brand.name`: antes intentaba pintar el objeto y solo no fallaba porque la API por slug no traía la marca. **Efecto visible:** en el detalle ahora aparece "MARCA · Categoría" cuando el producto tiene marca.
