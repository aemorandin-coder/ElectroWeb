# C-03 — Settings públicos
Estado: HECHO
Rama: claude/C-03 — **apilada sobre `claude/C-02`** (las dos tocan `app/page.tsx`, `app/productos/page.tsx` y las páginas de categorías). Mergear C-02 primero.

## Qué cambió
- **`lib/site-settings.ts`**
  - Nuevo `getPublicSettings()`, envuelto en React `cache`. Hace un `select` con **lista blanca**, así que los campos internos ni siquiera se leen de la BD. Tiene la misma forma que `/api/settings/public` más `primaryColor`, `secondaryColor`, `city` y `state`, que el header y la página de contacto ya usaban. Convierte Decimal a número, las fechas a ISO y los JSON a objeto. Si hay error o no existe la fila, devuelve los valores por defecto de siempre.
  - **Se quitó `'use server'`:** convertía cada export (`getSiteSettings`, `clearSettingsCache`) en una Server Action invocable desde el navegador. Solo lo importan módulos de servidor.
- **`app/layout.tsx`**
  - Lee `getPublicSettings()` y lo pasa a `Providers` → `SettingsProvider initialSettings`.
  - `export const revalidate = 60`. Sin esto, las páginas estáticas habrían congelado la tasa BCV del momento del build; ahora el build muestra todas con "Revalidate 1m".
- **`contexts/SettingsContext.tsx`:** ya no hace fetch al montar; `refreshSettings()` sigue disponible bajo demanda. El tipo pasa a `PublicSettings`, que es lo que realmente llega (tsc sin errores en los consumidores).
- **`/api/settings/public`** reutiliza `getPublicSettings()` (de 202 a 8 líneas).
- **`PublicHeader`, `Footer`, `WhatsAppButton`, `HotAdOverlay` y `DynamicFavicon`** leen `useSettings()` y ya no hacen fetch. `DynamicFavicon` pierde su caché en `localStorage`, que solo evitaba el parpadeo antes del fetch. `HotAdOverlay` tiene el cambio mínimo: su rediseño es C-23.
- **`<PublicHeader />` sin props sigue funcionando.** La prop `settings` se acepta y se ignora, para no romper las páginas que todavía la pasan.
- **Home, `/productos`, `/categorias` y `/categorias/[category]`:** `<PublicHeader />` sin `CompanySettings`. El home usa `getPublicSettings()` para el hero (misma consulta que el layout gracias a `cache`); las otras tres dejan de consultar settings.
- **`/api/settings` (PUT del admin)** llama a `revalidatePath('/', 'layout')` después de guardar, para que los cambios se vean sin esperar los 60 s.
