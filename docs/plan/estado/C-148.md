# C-148 · Cotizaciones para empresas e instituciones

Estado: HECHO (rama `claude/C-148`, sale de `main` con C-146; **lleva dos tablas nuevas**, aditivas). Queda una segunda parte (abajo, "Pendiente").

Idea que Andrés aprobó el 30/09 ("espectacular, podemos crear ese apartado"). El modelo son los presupuestos que él hacía a mano en HTML para sus clientes: mismo orden y mismo contenido, ahora dentro de la tienda.

## Cómo funciona

### El cliente pide una cotización (`/cotizacion`, sin cuenta)
- Formulario: empresa o nombre, RIF o cédula, persona de contacto, teléfono, correo, ciudad y qué necesita.
- Si tiene productos en el carrito, puede mandarlos para que se coticen.
- Enlaces: en el pie de página ("Cotizaciones para empresas") y en el carrito ("¿Compras para una empresa? Pide una cotización").
- Le llega al equipo como aviso **"Piden una cotización"** (panel, correo y Telegram) y aparece en el panel con un número (`PRES-2026-0001`).
- Con captcha y límite de 5 por minuto.

### El equipo la arma (panel → Cotizaciones)
- Menú nuevo **Cotizaciones**, con el contador de las que piden los clientes. Lo ve quien atiende órdenes.
- **Nueva cotización** o abrir una pedida. El editor tiene:
  - Cliente: empresa, RIF o cédula, contacto, teléfono, correo, ubicación y para qué es.
  - Equipos y servicios: se buscan en el catálogo (solo publicados) o se escriben como línea libre, con descripción, cantidad y precio. Una línea en $0 sale como "Incluido".
  - Condiciones: validez en días, anticipo en % (opcional), condiciones comerciales y entrega y garantía, una por línea.
  - El total, el IVA incluido, el anticipo y el saldo, a la vista.
- **Guardar y enviar al cliente** activa su enlace. Aparecen "Copiar enlace", "Enviar por WhatsApp" (al número del cliente, con el mensaje y el enlace) y "Abrir".
- **Vista previa** antes de enviarla: el enlace abre solo para el equipo.
- Después: "Volver a borrador" (apaga el enlace), "No se concretó" y "Borrar" (solo si el cliente nunca la vio).

### El cliente la abre con su enlace (`/cotizacion/<enlace>`, sin cuenta)
- El presupuesto como documento, con el orden de los de Andrés:
  1. **Membrete con el logo largo de la tienda** (el ícono y el nombre con la letra de la marca), razón social, RIF, dirección y contacto.
  2. Número, fecha y validez.
  3. Cliente, RIF o cédula, atención, ubicación y para qué es.
  4. Tabla de equipos: descripción, cantidad, precio unitario y total.
  5. Condiciones comerciales.
  6. Monto total, su equivalente en bolívares a la tasa BCV del día, **IVA incluido con la base imponible** (C-146), anticipo y saldo.
  7. Formas de pago (las activas en la tienda) y entrega y garantía.
  8. Firmas: por la empresa y por el cliente.
  9. "Este presupuesto no es una factura."
- **Imprimir o guardar en PDF:** sale solo el documento, en una hoja carta, con sus colores aunque el navegador tenga apagado "imprimir fondos".
- **Aprobar el presupuesto:** nombre, cédula o RIF y una casilla. Queda aprobada con fecha e IP, le llega al equipo el aviso **"Cotización aprobada"** y ya no se puede cambiar.
- Vencida la validez, la página lo dice y no deja aprobar.

## Reglas
- **El total lo calcula el servidor** con las líneas guardadas. Lo que mande el navegador (total, estado, enlace) se ignora.
- Los productos que elige un cliente al pedirla se cotizan con el precio de la tienda, nunca con el que mande el navegador.
- Un borrador no se ve con el enlace: solo las enviadas y las aprobadas.
- La página del cliente no muestra su correo, su teléfono ni la nota con la que la pidió. Los buscadores no la indexan.
- Una cotización aprobada no se edita, no se cierra ni se borra.
- No es un documento fiscal y no cobra nada: el pago se coordina después.

## Cambio de base (aditivo)
```sql
CREATE TABLE "quotes" (
    "id" TEXT NOT NULL,
    "number" TEXT NOT NULL,
    "token" TEXT NOT NULL,
    "status" TEXT NOT NULL DEFAULT 'DRAFT',
    "clientName" TEXT NOT NULL,
    "clientDoc" TEXT,
    "contactName" TEXT,
    "contactEmail" TEXT,
    "contactPhone" TEXT,
    "location" TEXT,
    "subject" TEXT,
    "requestNote" TEXT,
    "validityDays" INTEGER NOT NULL DEFAULT 15,
    "advancePercent" INTEGER,
    "conditions" TEXT,
    "terms" TEXT,
    "totalUSD" DECIMAL(65,30) NOT NULL DEFAULT 0,
    "taxPercent" DECIMAL(65,30) NOT NULL DEFAULT 0,
    "userId" TEXT,
    "createdById" TEXT,
    "sentAt" TIMESTAMP(3),
    "approvedAt" TIMESTAMP(3),
    "approvedName" TEXT,
    "approvedDoc" TEXT,
    "approvedIp" TEXT,
    "createdAt" TIMESTAMP(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
    "updatedAt" TIMESTAMP(3) NOT NULL,
    CONSTRAINT "quotes_pkey" PRIMARY KEY ("id")
);
CREATE TABLE "quote_items" (
    "id" TEXT NOT NULL,
    "quoteId" TEXT NOT NULL,
    "productId" TEXT,
    "title" TEXT NOT NULL,
    "description" TEXT,
    "quantity" INTEGER NOT NULL DEFAULT 1,
    "unitPriceUSD" DECIMAL(65,30) NOT NULL,
    "position" INTEGER NOT NULL DEFAULT 0,
    CONSTRAINT "quote_items_pkey" PRIMARY KEY ("id")
);
CREATE UNIQUE INDEX "quotes_number_key" ON "quotes"("number");
CREATE UNIQUE INDEX "quotes_token_key" ON "quotes"("token");
CREATE INDEX "quotes_status_idx" ON "quotes"("status");
CREATE INDEX "quote_items_quoteId_idx" ON "quote_items"("quoteId");
ALTER TABLE "quote_items" ADD CONSTRAINT "quote_items_quoteId_fkey" FOREIGN KEY ("quoteId") REFERENCES "quotes"("id") ON DELETE CASCADE ON UPDATE CASCADE;
```
Ningún `DROP` ni `ALTER ... TYPE`. Aplicado en `rev10_demo`.

## Archivos
- `prisma/schema.prisma`: modelos `Quote` y `QuoteItem`.
- `lib/cotizaciones/core.ts` (totales, estados y validación, compartido) y `lib/cotizaciones/index.ts` (numeración, guardado y lo que ve cada quien).
- APIs: `/api/cotizaciones` (pedir), `/api/cotizaciones/[token]` (aprobar), `/api/admin/cotizaciones` y `/api/admin/cotizaciones/[id]`.
- Páginas: `/cotizacion`, `/cotizacion/[token]`, `/admin/cotizaciones` y `/admin/cotizaciones/[id]`.
- `components/cotizaciones/`: el documento, las acciones del cliente y el formulario.
- `proxy.ts`: las dos rutas públicas de la API. `app/globals.css`: reglas de impresión del documento.
- Avisos nuevos: `QUOTE_REQUESTED` y `QUOTE_APPROVED` (se eligen en Notificaciones → Qué avisar).

## Después del deploy (Andrés)
1. **Configuración → Negocio:** revisa que estén el logo, la razón social, el RIF, la dirección, el teléfono y el WhatsApp. Salen en el membrete.
2. Panel → **Cotizaciones → Nueva cotización**: arma una de prueba con un producto del catálogo y una línea libre, con anticipo del 70 %. "Guardar y enviar al cliente".
3. Abre el enlace en tu teléfono: revisa el membrete con el logo, los montos y el IVA. Toca "Imprimir o guardar en PDF": debe salir una hoja.
4. Aprueba desde el teléfono: llega "Cotización aprobada" a la campana y a Telegram, y en el panel queda de solo lectura.
5. En la tienda, sin sesión: pie de página → "Cotizaciones" → llena el formulario. Llega "Piden una cotización" y aparece en el panel.
