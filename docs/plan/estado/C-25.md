# C-25 — La imagen del popup ya no viaja en todas las páginas
Estado: HECHO
Rama: claude/C-25 (desde `main` 3f0b983)

## El problema (medido en producción, 2026-09-14)
- En producción, `hotAdImage` estaba guardada **como texto base64 dentro de la BD** (378.654 caracteres), de una versión anterior de Marketing. Hoy Marketing ya sube la imagen como archivo.
- Los campos `hotAd*` iban dentro de `getPublicSettings()`, que el layout pone en **el HTML de todas las páginas** (`SettingsProvider`). Resultado: `/api/settings/public` pesaba 381 KB y el home 648 KB, y **cada página de la tienda cargaba esos ~380 KB** aunque el popup solo sale en el home.

## Qué cambió
- **`lib/site-settings.ts`:** se quitaron los 9 campos `hotAd*` de la configuración pública (tipo, `select` y valores por defecto).
- **`lib/queries/hot-ad.ts` (nuevo):** `getHotAd()` lee el popup solo cuando el home lo pide.
  - Imagen como archivo (`/uploads/...`) o `https://` → se usa tal cual.
  - Imagen en **base64** → se convierte en una URL corta `/api/public/hot-ad-image?v=<versión>` (hash de la imagen). **No hace falta volver a subirla ni tocar la BD.**
  - Solo PNG, JPEG, WebP o GIF. SVG, `javascript:`, `//otro-sitio` o `http://` → sin popup.
- **`app/api/public/hot-ad-image/route.ts` (nuevo):** decodifica el base64 y lo sirve como imagen.
  - Con la versión correcta: `Cache-Control: public, max-age=31536000, immutable`. Una imagen nueva trae otra versión; con una versión vieja se sirve la actual con caché de 5 min.
  - `X-Content-Type-Options: nosniff`, y 404 si el popup está apagado o la imagen no es base64 raster.
  - Es pública por el prefijo `/api/public` que ya tenía el proxy.
- **`components/HotAdOverlay.tsx`:** recibe `hotAd` como prop desde `app/page.tsx` (ya no usa `useSettings`).
  - Como la URL cambia con la imagen, los visitantes verán el popup una vez más al desplegar; después vuelve la regla de 24 h de C-23.

## Cómo se verificó
- **Pruebas unitarias** (`tsx`, Prisma simulado, PNG real de 1,2 MB): **17/17 PASS**.
  - **`getHotAd`:** el base64 se convierte en URL corta con versión; archivo y `https` se usan tal cual; SVG, `javascript:`, `//`, `http:` y base64 vacío → sin popup; desactivado → null.
  - **Ruta:** bytes idénticos al archivo original, `image/png`, caché immutable con la versión correcta y 5 min con una vieja, 404 para SVG, popup apagado o imagen como archivo.
  - **Configuración pública:** `getPublicSettings` ya no pide ningún campo `hotAd*` y los valores por defecto tampoco los traen.
- **Tienda de ejemplo** (esquema temporal `c25_demo`, borrado al final) **con el popup guardado en base64 de 1,58 MB**. Ninguna página contiene el base64 y la imagen responde `200 image/png` (1.181.542 B):

  | Página | Peso del HTML |
  | --- | --- |
  | `/` | 531 KB |
  | `/productos` | 247 KB |
  | Detalle de producto | 167 KB |
  | `/carrito` | 47 KB |
  | `/api/settings/public` | 1 KB |

  Antes, cada una llevaba además los 1,58 MB del popup.
- **Firefox por WebDriver BiDi:** **3/3 PASS**.
  - `/productos` no muestra el popup ni descarga su imagen.
  - En el home la imagen no se descarga hasta que el popup aparece (a los 2,5 s).
  - El popup sale con la imagen de la ruta cargada y el enlace `/productos`.
- `npx tsc --noEmit`: 0 errores. ESLint de los archivos tocados: limpio. `npm run build`: OK.
