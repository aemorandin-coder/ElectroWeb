# C-27 — Enlaces cortos para compartir productos
Estado: HECHO
Rama: claude/C-27 (desde `main` 9d715fb)

## El problema (visto en producción, 2026-09-14)
- La tienda ya tenía enlaces cortos (`/p/<código>`) y el botón Compartir los usa, pero **todos los productos de producción tienen `shortCode` vacío**. Por eso se compartía `electroshopve.com/productos/robux-saldo-para-roblox`.
- Solo el POST del asistente generaba el código; la carga masiva (`bulk/upload`) y la sincronización de SADES no.
- La redirección era **301**: el navegador la guarda para siempre, y el slug cambia al renombrar un producto → el enlace corto viejo acababa en 404.

## Qué cambió
- **`lib/short-code.ts` (nuevo):**
  - Código de 6 caracteres, con `crypto.randomInt` y sin caracteres confusos (0/o, 1/l/i). Ej.: `electroshopve.com/p/2hz8nw`.
  - `generateShortCode(db)` comprueba que no esté usado.
- **Se genera en los 3 lugares que crean productos:** asistente (`/api/products`), carga masiva y sincronización SADES.
- **`app/p/[code]/route.ts`:**
  - Redirección **307**, con el slug actual.
  - No distingue mayúsculas: `TEC1` y `tec1` llevan al mismo producto.
  - Borradores, archivados, códigos inexistentes o con caracteres raros → `/productos`.
- **`scripts/backfill-short-codes.ts` (nuevo):** da código a los productos sin código.
  - En seco solo cuenta; con `--apply` escribe.
  - Idempotente. No toca slugs ni otros campos.

## Cómo se verificó
- **Tienda de ejemplo** (esquema `c27_demo`, borrado al final) con 41 productos:
  - 40 sin código (como producción) y 1 con código viejo en mayúsculas (`TEC1`).
  - **Script:** en seco "Se asignarían: 40 · Ya tenían código: 1"; `--apply` asigna 40; la segunda corrida da "Se asignarían: 0".
- **Redirecciones** (`curl`):

  | URL | Resultado |
  |---|---|
  | `/p/2hz8nw` y `/p/2HZ8NW` | 307 → `/productos/procesador-intel-core-i3-12100-4-nucleos` |
  | `/p/TEC1` y `/p/tec1` | 307 → `/productos/teclado-gaming-aoas-small-keyboard-60-rgb-m-880` |
  | `/p/<código de borrador>`, `/p/noexiste`, `/p/a'b` | 307 → `/productos` |

- **Botón Compartir:** en la ficha y en las tarjetas del home ya lleva `/p/<código>`.
- `npx tsc --noEmit`: 0 errores. ESLint: archivos nuevos limpios; los 3 routes tocados no suman errores respecto de `main`. `npm run build`: OK.

## Despliegue (Andrés)
```bash
git pull && npm run build && pm2 restart electroshop-web
npx tsx scripts/backfill-short-codes.ts            # cuenta cuántos productos recibirán código
npx tsx scripts/backfill-short-codes.ts --apply
```
Sin cambios de esquema (la columna `shortCode` ya existía).
