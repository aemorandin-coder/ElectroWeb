# C-277 · El permiso de la lista de Verificaciones

Estado: HECHO

**De dónde sale (16/11):** del inventario de Clientes para el rediseño (C-276). `GET /api/admin/verifications` tenía el control de permiso vacío (el `if` sin `return`) y el proxy deja pasar a `/api/admin/*` a cualquier cuenta con sesión: un cliente cualquiera podía bajar el perfil completo de cada cuenta de empresa (cédula, teléfonos, RIF, direcciones, el carrito y la última IP). En producción hasta rc.90; cerrado en rc.91 el 16/11.

## Qué cambió
- `GET /api/admin/verifications` pide `MANAGE_USERS`, como el `PATCH` del mismo archivo.
- Entrega solo lo que muestra la pantalla de Verificaciones: la empresa, el RIF, el estado, los dos documentos, las notas y la fecha, con el nombre, el correo y la foto de quien la pidió. Antes iba el perfil entero.

## Cómo se verificó
- `npx tsc --noEmit`, `npm run lint` (0 errores), `npm run check:modulos` (Clientes 1.6.4), `npm run check:marca` y `npm run build`.
- **Contra la tienda de prueba, 8 de 8:**
  - **manipulado:** un cliente con sesión recibe 403 y ningún perfil; sin sesión, nada;
  - **normal:** el administrador con los dos pasos ve la empresa pendiente, solo con los campos de la lista blanca (sin cédula, teléfono, IP, carrito, direcciones ni fecha de nacimiento);
  - el `PATCH` de un cliente sigue en 403 y la empresa queda pendiente.

## Lo que queda
- Nada de código. En producción desde el 16/11 (rc.91, `HISTORIAL.md`): la subió Claude por SSH con la aprobación del equipo.
