# C-50a — Hotfix: la configuración completa era pública
Estado: HECHO
Rama: claude/C-50a (desde `main` 283cee4)

## El problema
- `proxy.ts` trataba como pública **cualquier ruta que empezara por `/api/settings`**.
- `GET /api/settings` no pedía sesión y devolvía la fila completa de `CompanySettings`, incluidos **`adminAlertEmails`** (correos del admin) y **`maintenanceAllowedIPs`** (IPs que se saltan el modo mantenimiento). CLAUDE.md prohíbe que esos campos salgan del servidor.
- Reproducido con el código de `main`: sin sesión → 200 con `adminAlertEmails` y `maintenanceAllowedIPs`.
- Además, `GET` y `PUT` devolvían `details: error.message` en los errores 500, que puede traer datos de la base de datos.

## Qué cambió
- **`app/api/settings/route.ts`:**
  - `GET` exige sesión: sin sesión → 401.
  - Permisos:
    - `MANAGE_SETTINGS`: configuración completa.
    - `MANAGE_PRODUCTS` (Productos lee tasas y moneda) o `MANAGE_CONTENT` (Marketing lee el popup): la misma configuración **sin** `adminAlertEmails` ni `maintenanceAllowedIPs`.
    - Cualquier otro → 403.
  - Los errores 500 ya no incluyen el mensaje interno.
- **`proxy.ts`:** solo `/api/settings/public` es pública (coincidencia exacta). La tienda usa esa ruta o `getPublicSettings()`.

## Cómo se verificó
- Prueba con Prisma y sesión simuladas: **16/16 PASS**.
  - Sin sesión → 401; cliente → 403; staff con solo `MANAGE_ORDERS` → 403.
  - Staff de productos o de marketing → 200 sin campos sensibles; `MANAGE_SETTINGS` y `ADMIN` → completo.
  - Sin fila: un cliente no la crea; el staff la crea sin exponer campos sensibles.
  - Errores de BD en `GET` y `PUT` → 500 sin el mensaje interno; `PUT` de cliente → 403.
  - Proxy: `/api/settings` sin token → bloqueado; `/api/settings/public` → pasa; `/api/settingsX` y `/api/settings/public/x` → bloqueados.
- La prueba del proxy de C-04 sigue en 30/30.
- `npx tsc --noEmit`: 0 errores. Lint de `app/api/settings/route.ts`: 6 → 4. `npm run build`: OK.

## Pendiente
- **Producción:** mientras no se despliegue, la ruta sigue abierta. Para comprobarlo, abrir `https://www.electroshopve.com/api/settings` en una ventana privada: si muestra JSON con `adminAlertEmails`, está expuesta. Tras desplegar, conviene revisar si esos correos reciben spam o phishing y cambiar la lista de IPs permitidas.
