# C-82 — Hotfix: aprobar cursos y creadores
Estado: HECHO
Rama: claude/C-82 (desde `main` con C-55)

## Qué reportó Andrés (producción, 16/09)
"Tengo un curso pendiente por aceptar y nunca se puede", con `TypeError: e.totalRevenue.toFixed is not a function` en la consola.

## Causas
1. **La página de creadores revienta en producción.** Producción corre una versión anterior: el `creator.totalRevenue.toFixed(…)` ya lo había quitado Gemini en R9 (G-26/G-33, `formatUSD`), pero no se ha desplegado. `totalRevenue` es un `Decimal` y llega del API como texto (`"320"`), que no tiene `toFixed`. **Se corrige con el deploy pendiente**; lo de abajo evita que vuelva a pasar y arregla lo que seguía mal en el código actual.
2. **No había forma de llegar a Cursos desde el menú del admin.** `/admin/cursos` solo se abría desde una notificación, y `/admin/creators` desde el dashboard. El contador de solicitudes de creador colgaba de "Marketing y Contenido".
3. **`formatUSD` mostraba $0,00 con montos en texto.** `formatAmount` usaba `Number.isFinite(value)`, que no convierte: los ingresos de un creador (`"320"`) salían en cero aunque la página ya no reventara.
4. **Aprobar un curso fallaba en silencio.** El botón "Activar" no revisaba la respuesta, y el `PATCH` hacía `prisma.course.update({ data: body })`: cualquier campo inesperado terminaba en un 500 sin mensaje. Además permitía reescribir dueño, inscritos o calificación (asignación masiva).
5. Nada distinguía un curso **en revisión** de uno desactivado, y el creador **no se enteraba** cuando se aprobaba.

## Arreglos
- **Menú del admin:** entradas **Cursos** (contador de cursos de creadores sin publicar) y **Creadores** (contador de solicitudes pendientes). `sidebar-counts` devuelve `pendingCourses`.
- **`lib/currency.ts`:** `formatAmount` convierte a número antes de validar. Arregla todos los montos que llegan como texto.
- **`PATCH /api/admin/courses/[id]`:**
  - Lista blanca `adminCoursePatchSchema` (zod, `strict`): 400 con el motivo en español.
  - Currículum validado con `curriculumSchema`.
  - Al pasar a activo un curso de creador, **notificación al creador** ("Curso aprobado", con enlace al curso).
- **`/admin/cursos`:** badge **"En revisión"** y botón verde **"Aprobar"** para cursos de creadores sin publicar; muestra el creador; avisos de éxito y de error (también al guardar el currículum).
- **`PATCH /api/admin/creators`:** solo acepta `PENDING`, `APPROVED`, `REJECTED` o `SUSPENDED`. La página avisa si falla.

## Otros mensajes de la consola de producción (no son bugs de código)
- **`/_next/static/chunks/….js` 404 y "MIME type text/plain":** la pestaña tenía HTML de un build anterior y pidió archivos que el build nuevo ya borró. Se arregla recargando. Pasa en cada deploy porque `npm run build` reemplaza `.next` **mientras el servidor viejo sigue atendiendo**. Para reducirlo: correr `pm2 restart` inmediatamente después del build.
- **`Blocked script execution in 'about:srcdoc'`:** es la vista previa de un correo dentro de un `iframe` con `sandbox`. Que no ejecute scripts es lo correcto.
- **Recharts `width(-1) and height(-1)`:** un gráfico se dibuja dentro de un contenedor todavía sin tamaño. Es un aviso, no rompe nada. Queda anotado para Reportes.
