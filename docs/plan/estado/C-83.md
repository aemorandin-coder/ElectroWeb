# C-83 — Hotfix: "Credenciales inválidas" al entrar después de registrarse
Estado: HECHO
Rama: claude/C-83 (desde `main`)

## Qué reportó Andrés (producción, 16/09)
Un cliente se registró y al entrar le salía "Credenciales invalidas". En la captura el correo está escrito en mayúsculas.

## Causa
- El registro guarda el correo en minúsculas (`email.toLowerCase().trim()`).
- El login lo buscaba **tal como se escribía** (`prisma.user.findUnique({ where: { email: credentials.email } })`). En PostgreSQL esa comparación distingue mayúsculas: "CONTACTO@…" o "Contacto@…" no encontraban la cuenta "contacto@…".
- Los campos de correo no tenían `autoCapitalize="none"`, así que el teclado del teléfono ponía la primera letra en mayúscula. Le pasa a cualquier cliente que se registre desde el teléfono.
- Lo mismo ocurría en "¿Olvidaste tu contraseña?" y en "Reenviar verificación": con mayúsculas decían "si el correo existe…" y no mandaban nada.
- El admin podía editar el correo de un cliente y se guardaba con mayúsculas.

## Arreglo
- `lib/correo.ts`: `normalizarCorreo` (minúsculas, sin espacios) y `buscarUsuarioPorCorreo`. Busca exacto y, si no encuentra, sin distinguir mayúsculas, para las cuentas viejas guardadas con mayúsculas.
- Se usa en: login (`lib/auth.ts`), registro (evita duplicar "Ana@…" y "ana@…"), recuperar contraseña, reenviar verificación y edición del cliente en el admin.
- Campos de correo de login, registro y recuperar contraseña: `inputMode="email"`, `autoCapitalize="none"`, `autoCorrect="off"`, `spellCheck={false}`.
- La validación del navegador rechazaba correos con `+` y dominios de más de 6 letras: ahora acepta cualquier correo con formato válido.
- Mensaje del login con tildes y más claro: "Correo o contraseña incorrectos. Revisa los datos e intenta de nuevo."

## Verificación
- `npx tsc --noEmit` 0 errores · `npm run build` OK · ESLint sin problemas nuevos.
- Pruebas contra el servidor (tienda de ejemplo, NextAuth real), las 7 pasan:
  - Registro con "Contacto@Franding-Demo.test" → 201, guardado en minúsculas.
  - Login con **"CONTACTO@FRANDING-DEMO.TEST"** → entra (el caso del cliente).
  - Login con "Contacto@franding-demo.test " (mayúscula y espacio al final) → entra.
  - Contraseña equivocada → sigue fallando.
  - Cuenta vieja guardada como "Legacy.Mayus@Demo.Test" → entra escribiéndola en minúsculas.
  - Registrar "legacy.mayus@demo.test" cuando existe "Legacy.Mayus@Demo.Test" → 400 "Este correo electrónico ya está registrado".

## Para el cliente mientras no se despliega
Que escriba el correo **todo en minúsculas**: su cuenta existe y la contraseña es la que puso.
