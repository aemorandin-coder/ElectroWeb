# C-88 — Contraseñas: una sola regla y recuperar la clave cierra las sesiones
Estado: HECHO
Rama: claude/C-88 (desde `main` con C-84 y C-86)

## Qué estaba mal (visto al preparar GPT-06)
- `POST /api/auth/reset-password` aceptaba claves de **6 caracteres**; el registro exige 8 con mayúscula, minúscula y número, y Configuración pedía solo 8. Cualquiera podía "bajar" su clave a `123456` con el enlace de recuperación.
- Recuperar la contraseña **no cerraba las sesiones abiertas**: si alguien había entrado a la cuenta, seguía adentro después de que el dueño la cambiara.
- Dos envíos a la vez con el mismo enlace cambiaban la clave dos veces; los otros enlaces pendientes del usuario seguían sirviendo.

## Arreglo
- `app/api/auth/reset-password/route.ts`: valida con `contrasenaSchema` (`lib/validations/registro.ts`); en una transacción borra el enlace (si ya no estaba, 400), cambia la clave con bcrypt 12, sube `sessionVersion` y borra los demás enlaces del usuario. La respuesta mantiene la clave `message` que lee la pantalla.
- `app/api/customer/settings/route.ts` (cambiar contraseña): misma regla y bcrypt 12. No cierra la sesión actual (para eso está "Cerrar todas las sesiones").

## Verificación
- `npx tsc --noEmit` 0 · `npm run build` OK · ESLint: sin problemas nuevos (los 3 de `customer/settings/route.ts` son de `main`).
- Contra el servidor (`next start`, esquema de ejemplo), 11 de 11: sesión abierta antes; clave de 6 → 400 "A tu contraseña le falta: 8 caracteres o más"; sin mayúscula → 400; válida → 200; mismo enlace otra vez → 400; otro enlace viejo del usuario → 400; **la sesión abierta antes quedó cerrada**; entra con la nueva; la vieja no entra; Configuración sin mayúscula → 400; válida → 200.
